What it is

A second opinion on a website, produced in minutes instead of days

Most small businesses have never had anyone look at their site properly. They know it "could be better," but nobody can tell them what is actually costing them calls. A proper agency audit is a paid engagement that comes back days later.

This tool answers it from a single pasted URL. It crawls the site, measures it with Google's own performance engine, checks the things that decide whether a local business shows up in search, and writes the result into two documents: a report that explains every problem in customer language, and a one page checklist of what to fix first, with an hour estimate next to each item.

Nothing in the output is an opinion or an estimate. Every number came from a request the tool made, and every finding names the page it came from.

How it works

Six stages, from a URL to a finished report

Each stage collects a different kind of evidence. Nothing is inferred from anything else, so a failure in one stage never invents a finding in another.

01

Read the site's own instructions

Fetches the homepage, then robots.txt and the XML sitemaps, including sitemap index files that point at other sitemaps. The rules a site publishes for crawlers are obeyed, so pages the owner asked search engines to skip are skipped here too, and recorded as skipped.

Collected
  • sitemap URL list
  • disallow rules
  • the real homepage after redirects
02

Crawl the whole site, not a sample

Works outward from the homepage and the sitemap at once, four pages at a time, pausing between requests so it stays a polite guest on someone else's server. Every page it reaches is read for 30 separate data points. It also counts how many internal links point at each page, which is how orphan pages get caught.

Per page
  • title, description, headings
  • word count, images, alt text
  • phone links, forms, schema
  • response time and size
03

Probe the connection itself

Some of the most expensive problems are invisible in a browser. This stage asks the server directly: does the insecure address redirect to the secure one, do the www and non-www versions resolve to a single site, does a made-up URL return a real 404 or a fake success page, and how long does the server take to answer at all.

Measured
  • redirect behaviour
  • 404 handling
  • time to first byte
  • compression, HTTP version
  • security headers
04

Test every link

Every internal destination the crawl found gets requested individually, along with up to 60 outbound links. Links that answer with a block rather than a failure, which is what most large sites do to any automated visitor, are listed separately instead of being reported as broken. The report says which page each dead link was found on.

Result
  • status code per link
  • the page that links to it
  • blocked separated from broken
05

Measure speed with Google's own tool

Runs Lighthouse, the engine behind Google's PageSpeed scores, twice: once emulating a phone on a mobile connection and once as a desktop. This matters because a site can feel instant on the owner's laptop and take five seconds on the phone their customers actually use.

Both profiles
  • performance, SEO
  • accessibility, best practice
  • core web vitals
  • ranked savings list
06

Score it, rank it, write it up

Everything collected runs through a rules engine that can raise 54 distinct findings. Each one carries a severity, the reason it costs money in plain language, the fix, an effort estimate, and the evidence it was drawn from. The findings roll up into five category scores and one overall number, and the whole thing is written to PDF.

Written out
  • 8 page report
  • 1 page work checklist
  • full raw data as JSON
What it checks

Fifty four findings across five areas

The categories are weighted by how directly they affect a local business getting the phone to ring: content and speed at 25 percent each, technical and local presence at 20, trust at 10.

Technical16 findings
  • HTTPS, and whether the insecure version still answers
  • www and non-www serving as two competing sites
  • Missing pages that return success instead of 404
  • Pages marked noindex, which removes them from Google entirely
  • robots.txt rules that block the site from search
  • Sitemap coverage checked against the actual crawl
  • Orphan pages nothing links to
  • Broken internal and outbound links
  • Canonical tags, duplicate page variants
  • Insecure assets loaded on a secure page
  • Security headers: HSTS, nosniff, CSP
Content and on page13 findings
  • Missing, duplicated, or badly sized page titles
  • Missing and duplicated meta descriptions
  • Pages with no headline, or several competing ones
  • Thin pages under 300 words
  • Alt text coverage across every image on the site
  • Whether the pages actually name the town they serve
  • Words a competitor leads with that this site never uses
  • Head to head against up to three competitors: the same checks on every site, the best marked, and what puts this site on top
  • Finds the competitors itself when none are given: a search for what the site does plus the town, with directories and social networks dropped
Local presence10 findings
  • Every phone number on the site, compared with the one Google shows
  • Different numbers appearing on different pages
  • Tap to call links, and how many pages actually have one
  • LocalBusiness structured data, the thing that feeds the Google panel
  • Street address, opening hours, map, contact form
  • Review markup, so stars can appear in results
Speed and trust15 findings
  • Mobile and desktop performance, scored separately
  • How long the screen stays blank, and whether it jumps while loading
  • Server response time, per page rather than just the homepage
  • Uncompressed pages and outdated HTTP versions
  • Accessibility failures, which also affect older customers
  • Analytics, social preview tags, favicon, stale copyright year
  • JavaScript errors, which usually mean a broken form nobody noticed

The checklist

One page, sorted by how long each job takes. Quick wins under an hour, work that fills a month, and the builds that need a day or more. This is the page that goes on the desk.

How it is kept honest

The tool is tested against a site with known faults

An audit tool that quietly stops catching things is worse than no tool, because the clean report is believed. So the project ships with a small website of its own, built to be broken in ten specific ways: a duplicated title, a page with no description, a page with no headline, two headlines on another, a four word page, a page hidden from search, a page nothing links to, an insecure image, a dead internal link, and a dead outbound one.

Running the audit against it has to return the same numbers every time. It catches all ten, scores the site 47 out of 100, and raises 24 ranked findings. Two of the ten sit below the thresholds that would promote them to a ranked finding, one duplicated headline and one dead outbound link, because a single instance of either is noise rather than a problem. Both still appear in the report's tables, which is the behaviour that is wanted: visible, but not dressed up as urgent.

Two consecutive runs produce identical output. Any drift in those numbers means a rule changed behaviour and something needs looking at.

Under the hood

No accounts, no API keys, no data leaving the machine

The whole thing is about two thousand lines of plain JavaScript with no build step and no framework. Speed comes from Lighthouse, pulled on demand by npx and driven through the copy of Edge that Windows already ships. Connection level facts come from curl. The PDFs are printed by the same browser. There is no third party service in the loop, which means no per audit cost, no rate limit, and nothing about a prospect's site sent anywhere.

Two modes

A free preview anyone can run, and the full audit behind it

The preview

Reads the homepage and five inner pages, runs one mobile Lighthouse pass, applies 19 checks, and produces a four page report plus a one page leave behind. It answers "is there a problem here" in about two minutes, which is the right length for a first conversation.

The full audit

Everything described on this page: the whole site, every link, the connection probes, both Lighthouse profiles, 54 findings and the eight page report. It runs only from the machine it is installed on, and every file it produces is refused to anyone else on the network.
